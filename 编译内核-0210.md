build linux kernel supporting UINTR and update in physical machine.

```bash
# Check current version
uname -r

git clone https://github.com/intel/uintr-linux-kernel.git --depth 1
cd uintr-linux-kernel
mkdir build

# default config  is 6.0.0+
cp /boot/config-6.0.0+ build/.config

make O=build -j16
make modules O=build -j16

sudo make modules_install O=build -j16
sudo make install O=build -j16

sudo update-grub
```

After installation, check if /boot/vmlinux-6.0.0+ exits.

Update Linux 6.0.0+ as default boot option in grub.

```bash
# check Ubuntu, with Linux 6.0.0+ seqence
sudo grep menuentry /boot/grub/grub.cfg
```

## 内核调试方法

### dynamic debug

`CONFIG_DYNAMIC_DEBUG` y ，机制已编入内核 debugfs 已挂载在`/sys/kernel/debug`

```bash
cd /home/zwp/uintr-linux-kernel
make -C build -j$(nproc) bzImage modules
sudo make -C build modules_install
sudo cp build/arch/x86/boot/bzImage /boot/vmlinuz-6.0.0+
sudo reboot

cd /home/zwp/uintr-linux-kernel/tools/testing/selftests/uintr

# 清零调试计数器
echo 0 | sudo tee /sys/module/uintr/parameters/recheck_enqueue
echo 0 | sudo tee /sys/module/uintr/parameters/recheck_on_set

# 跑 race 模式（会在失败时退出）
./syscall_wait_indefinite 200 race

# 查看计数器
echo "recheck_enqueue = $(cat /sys/module/uintr/parameters/recheck_enqueue)"
echo "recheck_on_set  = $(cat /sys/module/uintr/parameters/recheck_on_set)"
grep -E 'UIS|UKN' /proc/interrupts
```

```bash
# 打印kernel/uintr.c 1244行的pr debug
# f 打印 源文件名​ l 打印 行号​ m 打印 模块名​   p print（真正打印，不加这个不会输出） t 打印 线程 ID / CPU 信息
echo 'file uintr.c line 1244 +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control   # Pause for uintr
echo 'file uintr.c line 1265 +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control   # Returned from schedule
echo 'file uintr.c line 1544 +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control   # Waking up task

# 当然也可以直接全开
echo 'file uintr.c +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control

# 0xeb/0xec 两个中断处理程序（在 irq.c）
echo 'file irq.c format "*uintr*" +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control
```

脚本开启

```bash
cat > ~/uintr-dbg.sh <<'EOF'
#!/bin/sh
echo 'file uintr.c +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control
echo 'file irq.c format "*uintr*" +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control
EOF
chmod +x ~/uintr-dbg.sh

# 新增函数（`uintr_receiver_wait_indefinite` ）里的`pr_debug` 会自动出现在 control 列表里，按函数名开即可
echo 'func uintr_receiver_wait_indefinite +flmpt' | sudo tee /sys/kernel/debug/dynamic_debug/control
```

如何验证是否已经打开

```bash
sudo grep uintr.c /sys/kernel/debug/dynamic_debug/control | grep '=p' dmesg -wH # 另一个终端实时看
# 应看到 =p 标记 
sudo grep uintr.c /sys/kernel/debug/dynamic_debug/control | grep '=p' | head
```

看中断计数器

```bash
grep -E 'UIS|UKN' /proc/interrupts
```
/proc/interrupts Linux 内核导出的 每个 CPU 上中断计数
UIS / UKN 是 x86 UINTR 驱动在 /proc/interrupts 里注册的名字，
UIS​ UINTR Interrupt Sender（通知中断） 0xeb
UKN​ UINTR Kernel Notification（内核唤醒中断）0xec
